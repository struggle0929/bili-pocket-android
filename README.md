# 口袋 · 红包助手

Android 真机无障碍应用，在手机上读取 QQ 群通知或网页红包池，生成任务并操作手机哔哩哔哩。运行时不需要电脑、NapCat、模拟器或自建服务器。最低 Android 11。

当前为 **0.1.13 单账号预览版**。优先使用主空间的一个B站账号；在手机内按房间号调用 B站房间链接，不依赖电脑。HyperOS 弹出应用双开选择框时自动选择左侧主应用。双开调度尚未启用，实际验证范围见下文记录。

### 0.1.13 网页读取与操作入口（2026-11-05）

- 修复 [bili-lottery](https://bili-lottery.netlify.app/) 读取失败：该站通过 WebSocket 推送房间数据，不能套用旧站的 `/pool/api/state` 地址。默认自动识别网页声明的推送入口，并读取整表及房间增量；后台地址变化会重新发现，不写死临时域名。
- 设置 → 网页监控设置增加三种读取方式：自动识别、WebSocket、自定义 JSON。推送支持可选 WSS 地址覆盖与网站自己的 user/key，key 隐藏显示；默认留空。认证只发给选择的推送端点，不使用 B站密码或 Cookie。连接失败、首条数据超时和超过两分钟无更新均会重连，旧连接回调不会写入新来源。
- 自动识别保留原天选红包池格式，并支持 bili-lottery 数据格式。自定义 JSON 需要在消息页填写公开 HTTPS 接口，并在设置中明确映射列表、房间、条件、金额、金额单位与绝对开奖时间；根数组路径用 `$`，嵌套字段用点号。金额单位为 `gold`（100 金瓜子 = 1 电池）或 `battery`；时间单位为 `seconds`、`milliseconds` 或带时区的 `iso`。不按网页文字猜测金额，不执行下载的 JavaScript，不支持任意网页、验证码或登录态页面。
- 设置的大分组默认收起，点击标题展开/收起，并记住各分组状态。收起时关闭键盘，已经填写的配置仍保存。
- 任务队列点击房间卡片、消息页点击紫色“直播间信息”，均可复制房间号或提前打开 B站直播间。运行中菜单明确提示提前打开会先停止自动任务。手动打开不会标记已参与或自动点击红包。
- 设置 → 玄学抢红包增加“在抢红包页面多指点击红包”，默认关闭。仅在确认参与且能匹配当前红包卡片的等待阶段执行：随机 3～8 指，每轮 3 次短按，约每 1.8 秒一轮；仅点标题下方、金额附近的装饰区域，避开抢、领取、关闭按钮。开奖前 3 秒、页面不明确、离开 B站、关闭开关或停止运行后不再发起手势。没有证据表明此动作能提高中奖率。

96 项单元测试通过，覆盖推送字段、过滤、网址发现、JSON 单位与字段映射、多指数量与范围及停止条件。已在本机看到 Netlify 推送更新和新增任务，并验证新版折叠页面；此次测试只接收消息。多指点按的实际直播间效果仍需启用后观察，当前不承诺中奖效果。未恢复截图保存功能。

自定义 JSON 映射示例（只适用于已确认仅含电池红包的接口）：

```json
{"list":"data.list","room":"room_id","anchor":"uname","amount":"total_price","amountUnit":"gold","end":"end_time","timeUnit":"seconds","condition":"join_requirement","followValue":"1","fanclubValue":"2","onlyBattery":true,"id":"id","shares":"award_num"}
```

混合奖品接口应将 `onlyBattery` 改为 `kind` 字段路径与 `batteryValues` 数组；有额外领取限制时映射 `guard` 与允许值 `guardAllowed`。未知条件、额外限制、金额不明确、20 电池及以下、过期和黑名单仍只展示、不入队。网址不允许夹带查询参数或账号密钥；需要认证的网站使用单独的推送认证栏。

### 0.1.12 界面、消息源与记录（2026-11-05）

- 任务页只保留运行状态、开始/停止、清零和队列；权限与授权入口集中到设置。已结束任务默认收起，当前队列按开奖时间升序。底部四个标签与顶部标题适配系统导航栏、状态栏安全区域。
- 消息页每个红包独立成卡，按“消息来源、条件、直播间信息、红包信息”展示。可查看原文；不符合条件的信息也保留原因。
- 在消息页选择 QQ 群通知或网页监控。网页模式适配 [天选红包池](https://txhb.tangsong0v0.icu:8443/pool) 的 `/pool/api/state` 格式，默认每 5 秒刷新；不同结构的网站需要另行适配。
- 点网址输入框展开本地历史，点一条直接使用；右侧垃圾桶弹出删除确认。新网址在键盘确认或开始接收时保存到本地配置和历史。历史最多 20 条，重复网址去重；删除历史不停止当前监控。
- 网页仅把关注/粉丝团、超过 20 电池、有效未来开奖时间且不在黑名单的电池红包加入任务。天选、礼物、上舰与未知条件只展示。网页金额从金瓜子换算电池；过期数据、格式变化、连接失败不生成新任务。
- 网页模式无需 QQ 通知权限；后台监控由已连接的助手无障碍服务运行。消息页“开始接收”只收集信息，任务页“开始运行”才执行进房与参与。切换来源前需停止自动任务。
- 记录页按红包分块，顶部显示已确认参与、中奖次数、累计实际电池、单次最高、已结算中奖率和连续未中。新版持久保存参与确认标志；旧版仅从“已参与/中奖/未中奖”确认参与，不把未知结果推定成已参与。
- 已移除截图补记、截图目录选择及全部截图文件保存。页面识别仍使用内存中的临时画面；验证/异常停止只记录文字。CSV 保留导出并增加参与确认字段。

本机已覆盖安装并验证页面安全区域、网页抓取和任务生成、消息卡片、记录统计与网址历史/删除确认。81 项单元测试通过；数据库升级、参与标志和金额汇总另经 SQLite 检查。此次网页功能验证使用只接收模式，完整网页来源自动参与流程仍需实际运行观察。

### 0.1.11 新增（2026-11-05，仅代码与构建验证）

- 首页“任务”和“设置 → 任务与自动休眠”均增加 **清零连续未中奖**：立即清零当前计数并取消连续未中触发的休眠。历史记录、任务和验证锁定保留，已停止的任务不会因此自行启动。
- 进房时间默认以 60 秒为基准随机 ±10 秒，即提前 50～70 秒；留存默认至少 30 秒，额外增加 0～10 秒，即开奖后 30～40 秒。两项波动均可设为 0 关闭，基准和范围均可修改。每个任务首次排定后保存实际取值，轮询、重启不重新抽取；修改设置影响尚未排定的新任务。日志“任务时间”可查看实际取值。范围限制在 0～86400 秒；时间波动不保证避免平台识别。
- 同房任务继续按最长留存要求处理；没有后续同房任务时，留存到点即返回 B站首页。**首页确认成功后才能进入下一房间**，没有下一任务也会退出。通过 B站自己的启动入口清理其页面栈，避免重复打开房间造成嵌套。
- 连续未中触发休眠仍先完成留存与退出。进房重试也先返回首页；两次均无法确认退出就暂停任务。手动停止会立即停止操作，重新启动会先处理未退出的房间。
- 本版未连接手机、未覆盖安装；新增 UI、随机范围及退出流程只完成单元测试和签名构建，真机兼容性待验证。

## 下载与更新

在登录有权访问的 GitHub 账号后，打开 [私人 Releases](https://github.com/struggle0929/bili-pocket-android/releases)，下载 `pocket-live.apk` 并安装。同一签名且更高版本号的 APK 可以覆盖更新。预览版更新前可先导出记录。

这是私人仓库，未授权账号不能直接下载。APK 没有应用内自动更新安装功能，“GitHub 下载与更新”会打开 Releases。

单账号流程：QQ 通知回调配合每 5 秒活动通知补查；B站房间链接直达；HyperOS 应用选择框点击左侧主应用。参与前核对当前卡片金额和可用按钮；卡片有倒计时则核对，没有则在参与确认后校准时间。参与后默认发送“来了~”，明确中奖后默认发送“谢谢老板”。每个房间首次最多 1 电池入团需要开启设置中的对应开关；默认关闭，其他付费确认停止。实测期间使用电脑做开发和读日志，APK 运行本身不依赖电脑。

## 首次使用

1. 在手机 QQ、哔哩哔哩中完成自己的账号登录。
2. 安装 APK，打开助手的“设置”。开启助手的无障碍服务和 QQ 通知读取权限。Android/小米系统可能要求先在应用详情里允许受限设置。
3. 在 QQ 中开启目标群消息通知和消息内容展示；群处于免打扰、通知隐藏内容或 QQ 不发送完整文本时，助手无法从通知还原房间号和倒计时。
4. 填写“目标群通知标题关键词”，这里填 **群名称或其稳定片段**，不是 QQ 群号。默认 `B站直播区游戏群`，请按实际通知标题核对。
5. 在记录页选择导出目录，在设置中配置黑名单、进房与留存时间、连续未中奖阈值及休眠时长。
6. 在手机 B站直播间完成红包入口、面板关闭、关注弹窗关闭和表情路径标定。默认比例坐标只是起点，不同屏幕必须核对。
7. 点击“开始运行”，保持手机解锁、屏幕亮起，允许 QQ 和助手后台运行。可拖动彩字悬浮框，点击 × 停止。

消息页选择来源并接收红包卡片。QQ 模式需要目标群通知，网页模式无需 QQ；运行日志位于设置。网页读取方式见“网页监控设置”，连接失败会退避重试，数据超过两分钟未成功更新时暂停新的网页任务进房。

## 任务规则

- 只接受条件明确为“关注”或“粉丝团”的电池红包，必须具有有效房间链接和时间信息。
- 20 电池及更低金额直接跳过。点击前核对当前面板金额；不能用左上角入口倒计时核对轮播中另一张卡片。卡片自身有倒计时则核对，没有则在参与确认后校准对应任务。金额或状态不明确时不提交。
- 同房红包按任务时间处理，面板内用从右向左的滑动切换。
- 点击“抢”只算已提交；需要识别到参与确认后才按已参与处理。已参与后保持面板等待开奖。
- 开奖后读取明确结果，必要时重新打开面板。未知结果、未参与不累计“连续未中奖”。
- 中奖标题与领取按钮同时成立才记中奖；独立保存个人奖品数量、单位及证据，连续未中立即清零。数额无法识别时不使用红包总额代替。记录页汇总实际电池所得，CSV 包含数量和单位。
- 同房任务取最长留存截止时间；全部完成并留存到点后返回 B站首页，即使暂无下一任务。完成结果识别和已配置消息可能延后退出；确认已退出后才调度其他房间，不提前退出尚未完成的房间。
- 同日再次进入同一房间，禁用所有配置互动消息，避免重复打扰。
- 连续两次进房失败，当天跳过此房间。黑名单在消息接收及进房前检查。
- 达到连续未中奖阈值后休眠，默认 60 分钟后恢复；人机验证或限制提示触发的锁定需要人工处理后手动解除，不能靠定时恢复绕过。

## 自定义消息与表情

参与后默认只发送“来了~”，暂不自动发表情。参与后、明确中奖后和明确未中奖后分别配置动作。每行一个动作，从上到下执行：

```text
text:来了~
```

`text:` 后使用 `|` 分隔随机候选弹幕。`emoji:` 使用在这台手机上录制的完整点击路径；表情包必须先在 B站账号中可用。未标定的表情会记录“未发送”，不会假装成功。

中奖后默认：

```text
text:谢谢老板
```

发送顺序由行顺序决定，可以只发弹幕、只发表情或禁用互动消息。实际是否送达以 B站为准，点击发送不等于服务器确认送达。

## 记录与文件

任务数据库、消息卡片与网址历史留在应用本地。记录页可导出 CSV，包含房间、开奖时间、电池总额、条件、状态、账号、实际获奖数量、单位、证据文字和参与确认标志；**红包总额不是个人实际所得**。本版不保存图片。导出使用用户选择的目录，未选择时使用应用专属外部目录；卸载可能删除专属目录，请先导出。

网页模式读取所选站点或其声明的推送端点，不向它上传 QQ 通知、B站密码或 B站 Cookie。配置的网站 user/key 保存在应用私有配置中，仅用于对应网站的推送连接；不写入运行日志、网址历史或导出记录。私人 GitHub 只存源代码与发布 APK，不存运行数据或签名私钥。

## 已知限制

1. QQ 通知由系统和 QQ 决定是否发送、合并或截断；无障碍和通知权限不能保证完整读取所有群消息。当前使用通知源，不提供 PC/NapCat 中转。
2. 当前手机支持将主账号、双开账号的 B站都显示为悬浮窗口，两个房间可以同时驻留。**当前 APK 的跨窗口账号路由与并发调度尚未实现或验证**，仍按单账号串行调度，冲突任务可能排队后过期。悬浮双窗口是后续适配的基础，不等于当前版本已经支持双开任务。
3. 屏幕锁定、关闭、应用被系统结束、系统权限被回收、B站 UI 改动、验证码和通知缺失都可能停止或影响执行。截图被安全窗口禁止时只记录失败原因。
4. 不包含反检测、设备伪装、绕过验证码或账号限制的功能，也不保证中奖率。
5. 当前界面采用紫色强调、深色卡片和底部导航，参考 Tyranor 的配色与导航思路；未复制其素材。

## 本地构建

需要 JDK 17、Android SDK 35、Build Tools 35、联网下载 Gradle 和 Maven 依赖。

```powershell
$env:JAVA_HOME='C:\Program Files\Java\jdk-17.0.5'
.\gradlew.bat testDebugUnitTest assembleDebug
```

`local.properties` 中填写自己的 SDK 路径，该文件不提交。Parser 单元测试覆盖参与条件、20 电池过滤、消息时戳、跨午夜时间、歧义房间链接和黑名单整号匹配。

Windows 用户目录含中文时，如遇 `GradleWorkerMain` 无法加载，请将 `GRADLE_USER_HOME` 设为只含英文的可写目录后重试。开发机已通过仓库外的英文目录联接复用缓存；发布脚本会自动使用该目录。当前 Gradle 测试共 81 项，覆盖通知解析、参与证据、开奖提示、奖品数字识别、多红包选卡、时间范围、网页字段与金额换算、异常数据拒绝、网址历史及统计口径。

发布包使用独立签名，不依赖默认 debug 签名。当前开发机的私钥在仓库外 `D:\Github\android-build-tools\signing`，请妥善备份此目录；**不要上传私钥与密码**。可以运行 `build-release.ps1`，或自行设置：

```powershell
$env:POCKET_KEYSTORE='你的私钥路径'
$env:POCKET_KEYSTORE_PASSWORD='你的私钥密码'
.\gradlew.bat testDebugUnitTest assembleRelease
```

签名别名为 `pocket`。更新时必须保持 applicationId、签名不变，并递增 `versionCode`。

## GitHub Actions

推送到 main 或手动触发会运行单元测试和发布构建，APK 存在 Actions artifacts。推送 `v*` 标签会创建私人 Release 并附带 APK 和 SHA-256 校验文件。

签名通过仓库加密 Secrets 提供：`POCKET_KEYSTORE_BASE64`、`POCKET_KEYSTORE_PASSWORD`。源码、日志和构建脚本不包含私钥密码。缺少签名 Secrets 时工作流会失败，避免发布无法覆盖更新的替代签名。


## 0.1.1 授权与双窗口诊断

首页新增无障碍详情直达、QQ通知授权直达，分别显示权限与服务连接状态。详情页不受系统支持时回退至无障碍列表。停止任务不会撤销权限。若权限仍开启而服务未连接，检查应用后台限制、系统详情及服务状态，不应将两者混为一谈。

本机实测：覆盖安装成功，原有无障碍和通知权限保留；助手通过自身 API 分别读取到两个 B站小窗，窗口大小均为300×480。用户选择轮流放大、另一个保持小窗在线。设置中的放大左/右窗口测试用于下一步现场标定；目前尚未开放双账号自动任务调度。

## 0.1.2 放大与缩小循环测试

设置 → 应用双开增加左右窗口的“放大后自动缩小”测试。只允许停止任务后执行；先确认目标已放大和另一窗口存在，再尝试拖动顶部控制栏回角落，最后核对目标尺寸恢复为迷你窗口且另一窗口仍存在。缺少尺寸证据时记录“缩小待标定”，不会显示成功。缩小手势仍需本机现场验证，不代表双账号自动调度已经完成。

## 0.1.3 按本机实测修正缩小手势

用户实测指出：左侧窗口需长按右下角向左上拖动，右侧窗口需长按左下角向右上拖动。循环测试已采用这一操作，先连续按住400毫秒，再保持同一触点拖动900毫秒。窗口右/左下角由放大后的实际边界计算；仍以窗口尺寸恢复和另一窗口存在作为成功证据。旧版顶部控制栏拖动方案已移除。新手势需再次现场确认，双账号自动调度仍未开放。

## 0.1.4 双账号分配预览与进房路由验证

用户已实测确认 v0.1.3 左右窗口都能放大后缩小，另一窗口仍在线；本次启动约定左侧主账号、右侧备用账号。新增只读分配预览：同房红包合并至最晚开奖后留存；主账号优先、冲突才用备用；两个账号均无法赶上时显示冲突。预览不意味着已经进入房间或执行任务。

设置新增进房验证房间号和两项进房测试。主账号从助手发起链接，备用账号尝试执行目标 QQ 群窗口中该房间的原始无障碍链接操作，不通过普通 URLSpan 在助手自身账号环境打开链接。QQ 必须在目标群，链接需在当前可读取消息中。不支持的链接或窗口身份不匹配会记录日志。两项测试均不抢红包或发送消息，且需要人工核对房间号和账号昵称。双账号自动运行尚未开放，不能仅因放大缩小或窗口数量正常就视作账号路由正确。

## 0.1.5 两个账号统一按房间号进房

按用户要求移除了旧版 QQ 链接路径和进房测试中的外部深链接。两个账号统一定位对应B站窗口，放大后寻找搜索入口、输入房间号、提交搜索、选择直播结果并打开房间。搜索入口或直播结果无法唯一确认、出现验证码、目标窗口身份不确定时停止验证并记日志。不会点击任意视频或多个搜索结果中的第一个。房间号不再要求出现在 QQ 当前可见消息中。完整的房间号搜索流程仍需现场验证，自动双账号抢红包尚未启用。

## 0.1.6 修复停留在直播搜索页

本机截图确认直播结果展示“房间号：1754708052”，旧版仅按封面资源 ID 寻找卡片，漏识别该布局。新版本优先匹配明确的房间号标签，只接受号码完整一致，排除搜索框数字、前缀相似号码和多个卡片的聚合文字。点击最近的可点击卡片；没有可点击父控件时，只在经过窗口遮挡检查的精确房间号标签处点击。点击后等待直播间 Activity 或直播间控件确认，不重复点击搜索结果。
