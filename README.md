# 口袋 · 红包助手

Android 真机无障碍应用，直接在手机上读取目标 QQ 群通知、生成红包任务并操作手机哔哩哔哩。运行时不需要电脑、NapCat、模拟器或网络中转服务器。最低 Android 11。

这是 **0.1.0 真机适配预览版**。安装和构建成功不代表所有直播间流程已经实测通过；以手机上的任务状态、参与提示和结果截图为准。

## 下载与更新

在登录有权访问的 GitHub 账号后，打开 [私人 Releases](https://github.com/struggle0929/bili-pocket-android/releases)，下载 `pocket-live.apk` 并安装。同一签名且更高版本号的 APK 可以覆盖更新。预览版更新前可先导出记录。

这是私人仓库，未授权账号不能直接下载。APK 没有应用内自动更新安装功能，“GitHub 下载与更新”会打开 Releases。

## 首次使用

1. 在手机 QQ、哔哩哔哩中完成自己的账号登录。
2. 安装 APK，打开助手的“设置”。开启助手的无障碍服务和 QQ 通知读取权限。Android/小米系统可能要求先在应用详情里允许受限设置。
3. 在 QQ 中开启目标群消息通知和消息内容展示；群处于免打扰、通知隐藏内容或 QQ 不发送完整文本时，助手无法从通知还原房间号和倒计时。
4. 填写“目标群通知标题关键词”，这里填 **群名称或其稳定片段**，不是 QQ 群号。默认 `B站直播区游戏群`，请按实际通知标题核对。
5. 在助手选择记录导出目录和截图目录，配置黑名单、提前进房时间、留存时间、连续未中奖阈值及休眠时长。
6. 在手机 B站直播间完成红包入口、面板关闭、关注弹窗关闭和表情路径标定。默认比例坐标只是起点，不同屏幕必须核对。
7. 点击“开始运行”，保持手机解锁、屏幕亮起，允许 QQ 和助手后台运行。可拖动彩字悬浮框，点击 × 停止。

消息页展示收到的 QQ 通知和解析日志。没有收到通知与“通知已收到但字段不完整”是不同情况；请先查消息页，再查任务队列。

## 任务规则

- 只接受条件明确为“关注”或“粉丝团”的电池红包，必须具有有效房间链接和时间信息。
- 20 电池及更低金额直接跳过。点击前核对当前面板金额和倒计时；无法匹配时记录为无法确认，不猜测提交。
- 同房红包按任务时间处理，面板内用从右向左的滑动切换。
- 点击“抢”只算已提交；需要识别到参与确认后才按已参与处理。已参与后保持面板等待开奖。
- 开奖后读取明确结果，必要时重新打开面板。未知结果、未参与不累计“连续未中奖”。
- 按最少留存时间完成当前房间任务；没有到下个任务的进房时间时继续停留。不会为了抢后续任务提前退出尚未完成的房间。
- 同日再次进入同一房间，禁用所有配置互动消息，避免重复打扰。
- 连续两次进房失败，当天跳过此房间。黑名单在消息接收及进房前检查。
- 达到连续未中奖阈值后休眠，默认 60 分钟后恢复；人机验证或限制提示触发的锁定需要人工处理后手动解除，不能靠定时恢复绕过。

## 自定义消息与表情

参与后、明确中奖后和明确未中奖后分别配置动作。每行一个动作，从上到下执行：

```text
text:来啦！|好耶~|up↑up↑
emoji:EveOneCat2
```

`text:` 后使用 `|` 分隔随机候选弹幕。`emoji:` 使用在这台手机上录制的完整点击路径；表情包必须先在 B站账号中可用。未标定的表情会记录“未发送”，不会假装成功。

中奖后默认：

```text
text:谢谢老板
```

发送顺序由行顺序决定，可以只发弹幕、只发表情或禁用互动消息。实际是否送达以 B站为准，点击发送不等于服务器确认送达。

## 记录与文件

任务数据库和消息日志留在应用本地。记录页可导出 CSV，包含房间、开奖时间、电池总额、条件、参与/结果状态、账号和证据文字；**红包总额不是个人实际所得**。截图按用户选择的系统目录保存，未选择时使用应用专属外部目录。应用卸载可能删除专属目录，请先导出。

应用本身不包含上传通知原文、截图、账号密码或 Cookie 的服务。私人 GitHub 只存源代码与发布 APK，不存运行数据或签名私钥。

## 已知限制

1. QQ 通知由系统和 QQ 决定是否发送、合并或截断；无障碍和通知权限不能保证完整读取所有群消息。当前使用通知源，不提供 PC/NapCat 中转。
2. 当前手机支持将主账号、双开账号的 B站都显示为悬浮窗口，两个房间可以同时驻留。**当前 APK 的跨窗口账号路由与并发调度尚未实现或验证**，仍按单账号串行调度，冲突任务可能排队后过期。悬浮双窗口是后续适配的基础，不等于当前版本已经支持双开任务。
3. 屏幕锁定、关闭、应用被系统结束、系统权限被回收、B站 UI 改动、验证码和通知缺失都可能停止或影响执行。截图被安全窗口禁止时只记录失败原因。
4. 不包含反检测、设备伪装、绕过验证码或账号限制的功能，也不保证中奖率。
5. 当前界面采用紫色强调、深色卡片和底部导航，参考 Tyranor 的配色与导航思路；未复制其素材。

## 本地构建

需要 JDK 17、Android SDK 35、Build Tools 35、联网下载 Gradle 和 Maven 依赖。

```powershell
$env:JAVA_HOME='C:\Program Files\Java\jdk-17.0.5'
.\gradlew.bat testDebugUnitTest assembleDebug
```

`local.properties` 中填写自己的 SDK 路径，该文件不提交。Parser 单元测试覆盖参与条件、20 电池过滤、消息时戳、跨午夜时间、歧义房间链接和黑名单整号匹配。

Windows 用户目录含中文时，如遇 `GradleWorkerMain` 无法加载，请将 `GRADLE_USER_HOME` 设为只含英文的可写目录后重试。开发机已通过仓库外的英文目录联接复用缓存；发布脚本会自动使用该目录。当前 Gradle 测试共 19 项，包含面板金额与参与证据判定。

发布包使用独立签名，不依赖默认 debug 签名。当前开发机的私钥在仓库外 `D:\Github\android-build-tools\signing`，请妥善备份此目录；**不要上传私钥与密码**。可以运行 `build-release.ps1`，或自行设置：

```powershell
$env:POCKET_KEYSTORE='你的私钥路径'
$env:POCKET_KEYSTORE_PASSWORD='你的私钥密码'
.\gradlew.bat testDebugUnitTest assembleRelease
```

签名别名为 `pocket`。更新时必须保持 applicationId、签名不变，并递增 `versionCode`。

## GitHub Actions

推送到 main 或手动触发会运行单元测试和发布构建，APK 存在 Actions artifacts。推送 `v*` 标签会创建私人 Release 并附带 APK 和 SHA-256 校验文件。

签名通过仓库加密 Secrets 提供：`POCKET_KEYSTORE_BASE64`、`POCKET_KEYSTORE_PASSWORD`。源码、日志和构建脚本不包含私钥密码。缺少签名 Secrets 时工作流会失败，避免发布无法覆盖更新的替代签名。


## 0.1.1 授权与双窗口诊断

首页新增无障碍详情直达、QQ通知授权直达，分别显示权限与服务连接状态。详情页不受系统支持时回退至无障碍列表。停止任务不会撤销权限。若权限仍开启而服务未连接，检查应用后台限制、系统详情及服务状态，不应将两者混为一谈。

本机实测：覆盖安装成功，原有无障碍和通知权限保留；助手通过自身 API 分别读取到两个 B站小窗，窗口大小均为300×480。用户选择轮流放大、另一个保持小窗在线。设置中的放大左/右窗口测试用于下一步现场标定；目前尚未开放双账号自动任务调度。

## 0.1.2 放大与缩小循环测试

设置 → 应用双开增加左右窗口的“放大后自动缩小”测试。只允许停止任务后执行；先确认目标已放大和另一窗口存在，再尝试拖动顶部控制栏回角落，最后核对目标尺寸恢复为迷你窗口且另一窗口仍存在。缺少尺寸证据时记录“缩小待标定”，不会显示成功。缩小手势仍需本机现场验证，不代表双账号自动调度已经完成。

## 0.1.3 按本机实测修正缩小手势

用户实测指出：左侧窗口需长按右下角向左上拖动，右侧窗口需长按左下角向右上拖动。循环测试已采用这一操作，先连续按住400毫秒，再保持同一触点拖动900毫秒。窗口右/左下角由放大后的实际边界计算；仍以窗口尺寸恢复和另一窗口存在作为成功证据。旧版顶部控制栏拖动方案已移除。新手势需再次现场确认，双账号自动调度仍未开放。

## 0.1.4 双账号分配预览与进房路由验证

用户已实测确认 v0.1.3 左右窗口都能放大后缩小，另一窗口仍在线；本次启动约定左侧主账号、右侧备用账号。新增只读分配预览：同房红包合并至最晚开奖后留存；主账号优先、冲突才用备用；两个账号均无法赶上时显示冲突。预览不意味着已经进入房间或执行任务。

设置新增进房验证房间号和两项进房测试。主账号从助手发起链接，备用账号尝试执行目标 QQ 群窗口中该房间的原始无障碍链接操作，不通过普通 URLSpan 在助手自身账号环境打开链接。QQ 必须在目标群，链接需在当前可读取消息中。不支持的链接或窗口身份不匹配会记录日志。两项测试均不抢红包或发送消息，且需要人工核对房间号和账号昵称。双账号自动运行尚未开放，不能仅因放大缩小或窗口数量正常就视作账号路由正确。
